# Crucible 设计计划

> 产品：对标 Codex 的综合 agent —— Web 版 IDE 工作台。
> 流程：先出计划并自审，再写代码（frontend-design / design-taste-plus 的双遍要求）。

---

## 一、Brief 解读

| 项 | 结论 |
| --- | --- |
| **页面类型** | 高密度 IDE 工作台（editor + agent panel + terminal），**不是**落地页 |
| **受众** | 开发者。长时间盯着看，键盘优先，多显示器，容忍度高但对卡顿零容忍 |
| **语汇** | 工业、仪表、工程图纸、示波器、锻造台 |
| **模式** | greenfield |
| **基础** | 诚实美学家族：**dark tech / industrial control console**（不套 Material 或 shadcn） |

**明确不做什么**（design-taste-plus：本 skill 不面向 editor/dashboard，只取反 slop 规则 + 门禁）：

- 不做行内 ghost-text 补全（那是 Copilot 的活）—— 我们做侧栏 agent 工作台
- 不做营销页那套 hero → 三个等宽卡片 → CTA
- 不用 ui-ux-pro-max 推的 Aurora 渐变 + 紫盘（`#9E75C7`）。理由：
  1. 它自己把产品误判成「AI/ML Product」，推的是 SaaS 落地页结构（hero→pricing），与工作台无关；
  2. 紫色渐变正是 impeccable 与 design-taste-plus 双重点名的「AI slop」；
  3. 它自己库内的反模式清单写着 `❌ gradient cliche overload`，自相矛盾。

> 这与本项目前身（代码审查 agent）当初的判断一致：**只取它的 P0 门禁当约束，不采纳调色板。**

## 二、设计令牌

### 2.1 色彩：工业仪表盘

深色为主（开发者惯例），但**刻意规避三个 AI slop 陷阱**：
不用纯黑 `#000`；不用 tinted near-black 冒充黑；不用「近黑 + 单一酸性绿/朱红」。

| 角色 | 值 | 说明 |
| --- | --- | --- |
| `--bg` | `#10141A` | 带冷蓝的炭黑，不是纯黑 |
| `--surface` | `#161B22` | 面板底 |
| `--surface-raised` | `#1C222B` | 抬升面板 |
| `--border` | `#28303B` | 分隔线 |
| `--border-strong` | `#37414F` | 强调边框 |
| `--text` | `#D6DCE5` | 正文，非纯白 |
| `--text-muted` | `#8B95A5` | 次要 |
| `--text-faint` | `#5E6776` | 三级 |
| **`--brass`** | **`#C09440`** | **品牌色：黄铜。选中、焦点环、主行动** |
| `--brass-dim` | `#7A5F2A` | 黄铜的静默态 |
| `--jade` | `#3E9E76` | 语义：通过 / 成功 |
| `--amber` | `#E2A33C` | 语义：待批准（闸门） |
| `--vermilion` | `#CE4E45` | 语义：阻塞 / 错误 |
| `--slate-blue` | `#5A87B8` | 仅用于「信息」态，**不作品牌色** |

**为什么是黄铜**：撞车排查 —— VS Code 蓝、JetBrains 紫黄、Cursor 黑白、
代码审查 agent 深青 + 普鲁士蓝、ui-ux-pro-max 紫。
黄铜（老式示波器 / 航空仪表指示灯）在深色 IDE 里没人用过，既不是 AI 紫，也不是酸性绿。

语义色与品牌色**刻意分离**：审批闸门用亮琥珀，品牌用沉黄铜，视觉上可区分。

### 2.2 字体

**一套 IBM Plex 系统，两种角色** —— 一个家族，工业血统（Paul Rand 的 IBM 设计语言），
与「仪表台」主题自洽。**避开 Inter / Roboto / Arial**（impeccable 与 design-taste-plus 双重点名）。

- UI：**IBM Plex Sans** —— 界面、标签、叙述
- 代码：**IBM Plex Mono** —— 代码区、终端、diff、行号（真为代码设计，区分 `0/O`、`1/l/I`）
- 型阶（1.200 Minor Third）：11 / 12 / 13 / 15 / 19 / 23 / 28
- 代码区不用 `balance` / `pretty`（会破坏自然流），UI 标题用 `balance`，短正文用 `pretty`
- 所有会变的数字用 `font-variant-numeric: tabular-nums`

### 2.3 空间与形状

- 间距基数 4px，尺度：4 / 6 / 8 / 12 / 16 / 20 / 24 / 32
- **圆角体系（同心）**：`--r-sm 4px` / `--r-md 6px` / `--r-lg 10px`
  嵌套遵循 `outer = inner + padding`（zxh 的同心圆角）
- 分层阴影（非单层 `rgba(0,0,0,.1)`）：抬升面板用两层阴影
- 边框负责分隔与焦点环；阴影负责深度。各司其职

## 三、布局

```
┌──┬───────────┬──────────────────────────────┬──────────────┐
│活│ 侧栏       │ 编辑器区                      │  Agent 面板   │
│动│ (可切换)   │  ┌ 标签栏 ─────────────────┐  │ ┌ 模式条 ──┐ │
│栏│ ▸ 资源管理 │  │ auth.ts  auth.test.ts ×│  │ │ 计划视图  │ │
│  │  文件树    │  ├─────────────────────────┤  │ ├──────────┤ │
│44│ ▸ 会话历史 │  │ 行号 │ 代码 / diff       │  │ │ 事件流    │ │
│px│ ▸ 搜索     │  │      │                   │  │ │ 工具卡片  │ │
│  │ ▸ 源码管理 │  │      │                   │  │ │ 审批闸门  │ │
│  │           │  └─────────────────────────┘  │ ├──────────┤ │
│  │           ├──────────────────────────────┤ │ │ 输入坞    │ │
│  │           │ 终端面板 (可折叠)             │ └──────────┘ │
├──┴───────────┴──────────────────────────────┴──────────────┤
│ 状态栏：模型 · token 条 · 沙箱模式 · 审批策略 · 分支 · 行:列  │
└─────────────────────────────────────────────────────────────┘
```

**对齐**：整体左对齐、硬边、无居中。编辑器区是主角（宽度用 `minmax(0,1fr)`）。
**响应式**：1440 四栏常驻；≤1100 侧栏可折叠；≤900 agent 面板变覆盖式抽屉；
≤700 终端默认收起、活动栏转底部。

## 四、记忆点（boldness 只用一处）

### 审批闸门（The Approval Gate）

Codex 架构的灵魂是**沙箱 × 审批的正交双轴**。别的 IDE 把「要批准」做成右下角弹窗。
我们把它做成**事件流里的一道横向闸门**：

- 当 agent 要执行受门控动作（跑命令 / 写工作区外 / 联网），事件流**原地凝固**：
  一条带琥珀左光边的横条，左侧是动作摘要（`shell` / `apply_patch` / `网络访问`），
  右侧是「批准 · 批准并记住 · 拒绝」。
- 闸门下方一道虚线上标注 **「后续 N 个事件已暂缓」** —— 直观表达「流水线被截断」。
- 批准后闸门转 jade 绿并降为历史条目；拒绝则整段后续标记为未执行。

这个隐喻只在一处使用，周围一律克制。它同时是：视觉创新、架构自解释、可交互。

## 五、六 skill 落点

| Skill | 取了什么 |
| --- | --- |
| `design-taste-plus` | 反 slop 规则（禁 Inter 默认 / 禁 AI 紫 / 禁假截图 / 按钮全状态 / 禁随机深色区块）；dials：variance 8、motion 3（工具类要克制）、density 9（操作性内容） |
| `frontend-design` | 双遍流程（先计划后代码）；boldness 只花一处；避免「强调单个词/全大写标签/无意义数字编号」；文案用主动语态、动词一致、失败即指引 |
| `ui-ux-pro-max` | **只取 P0 门禁 12 条**（a11y 命名、4.5:1 对比、不靠颜色单独表意、键盘可达、焦点可见、无横向滚动、≥16px 正文…） |
| `impeccable` | AI Slop Test；DO/DON'T 表（禁纯黑白、禁 AI 紫渐变、禁万物皆卡片、禁 `transition: all`、禁弹跳缓动、用指数 ease-out） |
| `zxh-make-interfaces-feel-better` | 同心圆角、`balance`/`pretty`、`tabular-nums`、命名式 transition、press `scale(.96)`、热区 ≥40/44px、分层阴影、进入/退出动效拆分 |
| `web-design-guidelines` | 149 条：aria-label、语义标签、`:focus-visible`、`prefers-reduced-motion`、`color-scheme: dark`、`min-w-0`、溢出与空状态、`…` 与弯引号、`Intl.*` 格式化、破坏性操作用确认/撤销 |

## 六、图纸自审（对照 brief 复查）

逐条问「这个选择是不是我为任何 IDE 都会做的默认？」

| 检查点 | 结论 |
| --- | --- |
| 配色是「蓝 + 深灰」这个默认吗 | 否。黄铜主色 + 冷蓝炭底，是查过撞车表后的选择 |
| 字体是 Inter 吗 | 否。IBM Plex 双角色，有理由 |
| 是不是「万物皆卡片」 | 否。只有工具调用与闸门是卡片，其余是硬边分区 |
| 有没有 hero + 三卡 | 否，这是工作台 |
| 动效是否有理由 | 有。仅用于：事件流入场、闸门状态切换、面板开合。工具类不做装饰性动画 |
| 记忆点是否只有一处 | 是。只有审批闸门 |
| 是否尊重 `prefers-reduced-motion` | 会 |

**改了什么**：初版想让 agent 面板用淡紫作强调（跟「AI 感」不谋而合），
改为黄铜 —— 因为紫色是三重反模式，而黄铜在此语境无中生义、且唯一。
